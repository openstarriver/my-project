## 1. 项目背景

> 登录框 + 自我介绍页 + 轮播图 + 留言板，并接入一个大模型 API 做出一个真实 AI 功能。

**一句话定位**：一个单页个人站点 —— 访客登录后浏览站长介绍，在留言板留下一句话，收到 AI 回复。


## 2. 目标用户与场景

| 角色 | 场景 | 核心诉求 |
|---|---|---|
| 访客（首次到访） | 点开链接，迎面是登录页 | 没有账号怎么办？要能就地注册，而不是被挡在门外 |
| 访客（已登录） | 刷新页面、发表留言、删除留言 | 刷新不用重登；留言发得出、删得掉 |
| 站长（本人） | 改个人信息 / 看留言 | 改资料只改一处，不用翻模板 |

留言的人要的不是「提交成功」，是「被回应」—— 所以 AI 的每一次调用都必须有状态反馈。这条按**功能需求**对待，不按「体验优化」对待。

### 3.2 模块说明

#### 3.2.1 登录 / 注册

- **账号存储**：账号列表存 localStorage（键 `zhangxianghang_credential`）。首次打开时存储为空，回落到内置账号 `123456 / 123456`，并且**在错误提示里直接把账号写出来** —— 不让访客因为不知道密码而卡在门口。
- **登录校验**：账号去空格后与已注册账号逐一比对，全部匹配才放行。空值与不匹配分别给提示，均不跳转。
- **注册校验**：账号密码非空 → 两次密码一致 → 账号不重复，三道依次拦下；通过后 `push` 追加（而非覆盖）已有账号并切回登录页。
- **登录态**：单独存在 `zhangxianghang_loggedIn`，与账号数据解耦 —— 退出登录只清登录态，不影响已注册的账号。**必须在 `setup` 里就同步读一次**：留到 `onMounted` 再赋值，已登录用户的每次刷新都会先闪一下登录表单。

#### 3.2.2 自我介绍

全部信息收在 `introData` 一个对象里，模板只负责渲染。改资料只动这一处，「改一处即可」在这里兑现。头像走 `public/` 绝对路径引用，构建时原样拷到网站根目录。

#### 3.2.3 轮播图

5 张幻灯片，1.5 秒自动切换，配左右按钮、底部指示点和「第 n / 5 张」计数。位移由计算属性驱动的 `transform` 实现，不手动操作 DOM。四个细节各有其因：

- 鼠标移入暂停、移出继续 —— 想看清某一张时不该被抢走；
- 手动切换后**重置计时器**，否则刚点完「下一张」旧定时器立刻到点，观感上像点一次跳了两张；
- 重置前先清旧定时器 —— 鼠标反复进出会叠起多个 `setInterval`，播放越来越快；
- 组件卸载时清掉定时器，避免泄漏。

#### 3.2.4 留言板

- **持久化**：留言存 localStorage（键 `zhangxianghang_messages`），**先落盘再请求 AI** —— AI 挂了，留言本身刷新后也不会丢。落盘时只写稳定字段，`aiStatus` / `aiError` 这类临时态不存，否则刷新后会永久卡在「正在思考…」。写盘失败则回滚刚插入的这条，不让界面与存储对不上。
- **展示**：按时间正序存放、倒序展示，最新一条在最上面。
- **防重复提交**：提交期间按钮置灰，函数入口再挡一道 —— 按钮虽然 disabled，在输入框里按回车照样会触发表单的 `submit`，不拦就会连发两条留言、并排打两次 AI 接口。
- **删除**：先播 300ms 淡出动画，再真正移除数据并同步存储（F8）。
- **id 生成**：`时间戳 + 自增序号`。纯用 `Date.now()` 的话，同一毫秒内连发两条会拿到相同 id，删一条会连带删掉另一条。

#### 3.2.5 AI 回复链路

- **调用路径**：前端请求同站点内的 `/api/chat`，由 Vercel 服务端函数转发到上游（当前为通义千问 `qwen-max`）。上游地址由环境变量 `BASE_URL` 提供，换模型只改环境变量，前端不动。
- **安全边界**：**API Key 只存在服务端环境变量里，不下发到浏览器** —— 这是安全边界，不是可选项。
- **人格设定**：系统提示词约束了回复的语气与长度（50–150 字），前端按 `temperature 0.8`、`max_tokens 300` 请求。
- **三态反馈（F9）**：请求中显示「正在思考…」+ 动画点，成功显示回复，失败显示可读的错误文案；上游的原始报错不直接透给访客，只给状态码。

## 4. 数据设计

站点无数据库，全部数据落在浏览器 localStorage 的三个键上，互相独立：

| 键名 | 内容 | 字段 | 生命周期 |
|---|---|---|---|
| `zhangxianghang_credential` | 已注册账号数组 | `account`、`password` | 注册时追加；为空或损坏时回落内置账号 |
| `zhangxianghang_loggedIn` | 登录标记（字符串 `'true'`） | — | 登录成功写入，退出登录清除；删掉它不影响账号 |
| `zhangxianghang_messages` | 留言数组 | `id`、`name`、`content`、`time`、`aiReply` | 发表时写入，删除时移除；`aiStatus`、`aiError` 为运行时临时态，**不落盘** |

读取侧一律做容错：凭证额外校验每个元素都带账号密码字段，留言只校验顶层是数组，任何解析异常都降级为空列表 / 初始账号，不让一条脏数据把整页拖白。

## 5. 非功能需求

| 类型 | 要求 | 落实方式 |
|---|---|---|
| 健壮性 | 本地存储被改坏时不能白屏 | 读取凭证：`Array.isArray` + 元素字段双重校验，过滤掉 `[null]` 这类残缺项；读取留言：`Array.isArray` 兜底。异常一律降级初始账号 / 空列表 |
| 健壮性 | 上游异常时必须返回结构化 JSON | `/api/chat` 内四条路径全部返回统一格式：① 非 POST → 405；② 缺环境变量 → 500；③ 上游返回非 JSON → 自行解析并降级为可读报错；④ 请求上游抛错 → 502。先按文本读再解析，是为了让第 ③ 条不会把异常直接抛出去 |
| 可维护性 | 站点内容与模板分离 | 个人信息（`introData`）、幻灯片（`slides`）为独立常量，改内容不碰模板；AI 人格提示词集中在 `callQwenMax` 内，未散落在模板中 |
| 可部署性 | 一条命令上线 | Vite 构建，Vercel 托管，前端与 Serverless 函数同仓，`npm run build` 产出即可部署 |
| 响应式 | 手机上可正常打开 | 视口 meta + 深色 `theme-color`，避免手机地址栏出现白边 |
| 交互体验 | AI 回复流式输出（F10） | **尚未落实**：当前 `/api/chat` 一次性返回、前端整体渲染；改造需服务端函数改为流式转发，前端按增量追加渲染 |

## 9. 我踩的坑

招新文档要求「至少记录一次 AI 生成的代码出了问题 —— 你如何发现、如何修复」。下面 9.3、9.4 是这一类，9.1、9.2 是我自己的理解偏差，付出的代价更大。

### 9.1 把 Vue 当成一个「软件」

- **现象**：两个项目塞进同一个文件夹后集体报错，什么都打不开。
- **原因**：刚接触 Vue 时，我以为一个项目只有一个 `.vue` 文件，把 `App.vue` 当成所有项目的统一入口。
- **解决**：一遍遍问 AI，才理清 Vue 的项目 / 入口 / 组件三层关系。

### 9.2 挪了文件位置，没改引用路径

- **现象**：调整过目录结构后一片引用错误，怎么调都调不回来。
- **原因**：脚手架和 `App.vue` 都是 AI 搭的，我误以为文件放哪都行 —— 我改的是文件夹的存放顺序，`App.vue` 里的相对路径没跟着改。
- **解决**：全部删掉，从零重来一遍。**教训：动文件之前，先看清谁在引用它。**

### 9.3 密钥隐藏不能全交给 AI（两次翻车）

- **第一次**：让 Claude Code 手抄密钥，它抄漏了一位 —— 页面不报错，只有 AI 回复一直失败、那块区域是灰的。靠开发者工具逐项排查，才发现密钥不完整。
- **第二次**：密钥其实已经藏在 Vercel 环境变量里，Claude Code 却断定我的密钥「完全泄露」，催我立刻更换并推荐一套「新方法」。争论半天它才承认两者是同一件事 —— 它把我另一个文件夹里未隐藏密钥的 HTML 版本当成了 Vue 版。
- **教训**：**AI 的结论要问依据，别被它的语气带走**；密钥这种事，自己确认一遍才作数。

### 9.4 icon 图片「找得到、放不对」

- **现象**：让 AI 帮忙找图标，最后图片没出现在该出现的位置，项目里也搜不到文件。
- **解决**：自己找图、改尺寸，放进 `public/` 的指定位置。
